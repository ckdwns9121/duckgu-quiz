JavaScript 핵심

호이스팅, 클로저, this, 비교 연산, 복사처럼 면접과 코드 리뷰에서 가장 많이 헷갈리는 것만 모았습니다.

JS

var 호이스팅

console.log(a);
var a = 1;
console.log(a);

출력은? (여러 줄이면 띄어쓰기로 이어서)

undefined 1
  1. var a 선언이 맨 위로 끌어올려진 것처럼 동작하고, 값은 undefined로 시작
  2. 첫 console.log(a) → undefined (에러가 아님)
  3. a = 1 대입 뒤 두 번째 출력 → 1

기억할 것: var는 선언만 올라가고 값은 안 올라간다. let·const였다면 첫 줄에서 ReferenceError.

JS

클로저 카운터

function makeCounter() {
  let n = 0;
  return () => ++n;
}
const c1 = makeCounter();
const c2 = makeCounter();
console.log(c1(), c1(), c2());

출력은? (여러 줄이면 띄어쓰기로 이어서)

1 2 1
  1. makeCounter()를 부를 때마다 새 n이 만들어짐
  2. c1은 자기 n을 기억 → 1, 2
  3. c2는 따로 만든 n → 1

기억할 것: 클로저는 만들어질 때의 변수를 각자 따로 기억한다. c1과 c2는 서로의 n을 모른다.

JS

var + setTimeout 반복문

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}

출력은? (여러 줄이면 띄어쓰기로 이어서)

3 3 3
  1. var i는 반복문 전체에서 하나뿐
  2. setTimeout 콜백은 반복문이 다 끝난 뒤 실행 → 그때 i는 3
  3. 세 콜백이 같은 i를 보므로 3이 세 번

기억할 것: var는 함수 스코프라 반복마다 새로 안 생긴다. 해결: let으로 바꾸기.

JS

let + setTimeout 반복문

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}

출력은? (여러 줄이면 띄어쓰기로 이어서)

0 1 2
  1. let i는 반복마다 새 i가 만들어짐
  2. 각 콜백이 자기 반복의 i를 기억 (클로저)
  3. 0, 1, 2 순서로 출력

기억할 것: let은 블록 스코프라 반복마다 새 변수. var 문제와 짝으로 외우기.

JS

this와 call

const obj = {
  name: 'A',
  hi() { return this.name; },
};
console.log(obj.hi());
console.log(obj.hi.call({ name: 'B' }));

출력은? (여러 줄이면 띄어쓰기로 이어서)

A B
  1. obj.hi() → 점 앞의 객체(obj)가 this → A
  2. obj.hi.call({ name: 'B' }) → call로 넘긴 객체가 this → B

기억할 것: 일반 함수의 this는 어떻게 불렀는지로 정해진다. 점 앞의 객체, 또는 call·apply·bind로 넘긴 객체.

JS

== 와 ===

console.log(0 == '0');
console.log(0 === '0');
console.log(null == undefined);
console.log(null === undefined);
console.log(NaN === NaN);

출력은? (여러 줄이면 띄어쓰기로 이어서)

true false true false false
  1. 0 == '0' → 타입을 맞춰 비교 → true
  2. 0 === '0' → 타입이 다름 → false
  3. null == undefined → 특별 규칙으로 true
  4. null === undefined → false
  5. NaN === NaN → NaN은 자기 자신과도 다름 → false

기억할 것: ==는 타입을 바꿔서 비교, ===는 타입까지 비교. NaN 확인은 Number.isNaN().

JS

typeof 함정

console.log(typeof null);
console.log(typeof []);
console.log(typeof undefined);
console.log(typeof function () {});

출력은? (여러 줄이면 띄어쓰기로 이어서)

object object undefined function
  1. typeof null → object (JS 초기 설계 버그가 그대로 남음)
  2. typeof [] → 배열도 object
  3. typeof undefined → undefined
  4. typeof function(){} → function

기억할 것: null과 배열은 typeof로 구별이 안 된다. 배열은 Array.isArray(), null은 === null.

JS

spread 얕은 복사

const a = { x: 1, inner: { y: 1 } };
const b = { ...a };
b.x = 2;
b.inner.y = 2;
console.log(a.x, a.inner.y);

출력은? (여러 줄이면 띄어쓰기로 이어서)

1 2
  1. { ...a }는 바깥 객체만 새로 만든다
  2. b.x = 2 → b만 바뀜 → a.x는 1
  3. b.inner는 a.inner와 같은 객체 → a.inner.y도 2

기억할 것: spread는 얕은 복사. 안쪽 객체까지 복사하려면 structuredClone().

JS

truthy · falsy

console.log(Boolean(''));
console.log(Boolean('0'));
console.log(Boolean([]));
console.log(Boolean(0));

출력은? (여러 줄이면 띄어쓰기로 이어서)

false true true false
  1. '' 빈 문자열 → false
  2. '0' 글자가 있는 문자열 → true
  3. [] 빈 배열도 객체라 → true
  4. 0 → false

기억할 것: falsy는 false, 0, '', null, undefined, NaN 여섯 개뿐. 나머지는 빈 배열·빈 객체까지 전부 truthy.

JS

|| 와 ?? 와 ?.

const u = { n: 0 };
console.log(u.n || 5);
console.log(u.n ?? 5);
console.log(u.x?.y);

출력은? (여러 줄이면 띄어쓰기로 이어서)

5 0 undefined
  1. u.n || 5 → 0은 falsy라 5
  2. u.n ?? 5 → ??는 null·undefined일 때만 뒤를 씀 → 0
  3. u.x?.y → u.x가 없으니 에러 대신 undefined

기억할 것: ||는 falsy면 대체, ??는 null·undefined일 때만 대체. 0이나 빈 문자열을 살리고 싶으면 ??.

JS

화살표 함수의 this

  • 선언된 위치의 바깥 스코프 this를 그대로 쓴다
  • 호출한 객체(점 앞의 객체)를 가리킨다
  • 항상 전역 객체(window)를 가리킨다
  • call로 넘긴 객체로 바뀐다

화살표 함수의 this는 어떻게 정해질까?

화살표 함수는 자기 this가 없어서 바깥의 this를 그대로 쓴다. call·apply·bind로도 바꿀 수 없다. 그래서 객체 메서드로 쓰면 this가 객체를 가리키지 않는다.

console.log(
  [1, 2, 3, 4]
    .filter((n) => n % 2 === 0)
    .map((n) => n * 10)
    .reduce((s, n) => s + n, 0)
);

filter로 짝수 [2, 4] → map으로 [20, 40] → reduce로 더해서 60. filter를 빼먹으면 100, map을 빼먹으면 6.

PART 2

비동기 · 이벤트 루프

console.log 출력 순서 문제는 면접 단골입니다. 동기 코드 → 마이크로태스크 → 매크로태스크 순서만 확실히 잡으면 됩니다.

이벤트루프

setTimeout vs Promise

console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);

출력은? (여러 줄이면 띄어쓰기로 이어서)

1 4 3 2
  1. 동기 코드 먼저: 1, 4
  2. 동기 코드가 끝나면 마이크로태스크(Promise.then) 전부: 3
  3. 그다음 매크로태스크(setTimeout): 2

기억할 것: 동기 → 마이크로태스크 → 매크로태스크. setTimeout 0초여도 Promise.then보다 늦다.

이벤트루프

queueMicrotask

setTimeout(() => console.log('t'), 0);
queueMicrotask(() => console.log('m'));
console.log('s');

출력은? (여러 줄이면 띄어쓰기로 이어서)

s m t
  1. 동기 코드: s
  2. queueMicrotask는 마이크로태스크 → m
  3. setTimeout은 매크로태스크 → t

기억할 것: queueMicrotask는 Promise.then과 같은 줄(마이크로태스크 큐)에 선다.

async

await 뒤의 코드

async function f() {
  console.log('a');
  await null;
  console.log('b');
}
f();
console.log('c');

출력은? (여러 줄이면 띄어쓰기로 이어서)

a c b
  1. f() 안의 console.log('a')는 바로 실행 → a
  2. await를 만나면 f의 나머지는 마이크로태스크로 미뤄짐
  3. 바깥 동기 코드 → c
  4. 마이크로태스크로 f 재개 → b

기억할 것: await 앞은 동기, await 뒤는 마이크로태스크. async 함수도 처음 await 전까지는 그냥 동기 코드.

이벤트루프

then 안에서 setTimeout

Promise.resolve()
  .then(() => {
    console.log(1);
    setTimeout(() => console.log(2));
  })
  .then(() => console.log(3));
setTimeout(() => console.log(4));

출력은? (여러 줄이면 띄어쓰기로 이어서)

1 3 4 2
  1. 처음에 등록: 첫 then(마이크로), setTimeout 4(매크로)
  2. 마이크로태스크: 첫 then → 1, 이때 setTimeout 2를 등록 (4 뒤에 줄 섬)
  3. 이어서 두 번째 then → 3
  4. 매크로태스크는 줄 선 순서대로: 4, 2

기억할 것: 마이크로태스크는 큐가 빌 때까지 이어서 실행되고, 매크로태스크는 등록된 순서대로 하나씩.

Promise

Promise 생성자 안의 코드

new Promise((resolve) => {
  console.log('p');
  resolve();
}).then(() => console.log('then'));
console.log('end');

출력은? (여러 줄이면 띄어쓰기로 이어서)

p end then
  1. new Promise(콜백)의 콜백은 즉시 동기로 실행 → p
  2. then은 마이크로태스크로 미뤄짐
  3. 동기 코드 → end
  4. 마이크로태스크 → then

기억할 것: Promise 생성자 콜백(executor)은 동기, then·catch·finally만 비동기.

이벤트 루프 한 바퀴

이벤트 루프가 한 바퀴 도는 순서대로 놓으세요.

  1. 콜 스택의 동기 코드
  2. 마이크로태스크 전부
  3. 화면 렌더링 (필요할 때)
  4. 매크로태스크 하나

지금 실행 중인 코드(콜 스택)가 끝나면 마이크로태스크를 큐가 빌 때까지 전부 실행하고, 필요하면 화면을 그린 뒤, 매크로태스크를 하나 꺼낸다. 이것을 반복한다.

Promise

Promise 조합

  • 바로 실패(reject)하고 그 에러를 돌려준다
  • 전부 끝날 때까지 기다린 뒤 성공한 것만 돌려준다
  • 실패한 것만 빼고 성공으로 끝난다
  • 실패한 것을 한 번 더 시도한다
  • Promise.allSettled
  • Promise.all
  • Promise.race
  • Promise.any

Promise.all([p1, p2, p3]) 중 하나가 실패하면?

all: 전부 성공해야 성공, 하나라도 실패하면 바로 실패. allSettled: 성공·실패 결과를 모두 모아 줌. race: 가장 먼저 끝난 것(성공이든 실패든). any: 가장 먼저 성공한 것.

이벤트루프

setTimeout(fn, 0)

  • 지금 코드와 마이크로태스크가 모두 끝난 뒤
  • 바로 다음 줄보다 먼저
  • 0ms 뒤 지금 코드를 멈추고 즉시
  • Promise.then보다 먼저

setTimeout(fn, 0)의 fn은 언제 실행될까?

0ms라도 매크로태스크라서 콜 스택이 비고 마이크로태스크가 다 끝나야 실행된다. 실제로는 브라우저가 최소 지연을 둘 수도 있다.

경로(/other/page)는 출처에 들어가지 않는다. 프로토콜(http), 호스트(api.a.com), 포트(8080) 중 하나라도 다르면 다른 출처.

다음 중 리플로우 없이 처리돼 애니메이션에 가장 좋은 속성은?

transform과 opacity는 레이아웃·페인트를 건너뛰고 합성 단계만 다시 해서 부드럽다. width·top·margin은 바꿀 때마다 리플로우가 일어난다.

이벤트

DOMContentLoaded vs load

  • DOMContentLoaded는 HTML 파싱이 끝나면, load는 이미지·CSS까지 다 받으면 발생한다
  • load는 HTML 파싱이 끝나면, DOMContentLoaded는 이미지까지 다 받으면 발생한다
  • 둘은 항상 같은 시점에 발생한다
  • DOMContentLoaded는 이미지가 다 떠야 발생한다

DOMContentLoaded와 load에 대한 설명으로 맞는 것은?

DOMContentLoaded: DOM이 다 만들어진 시점 (defer 스크립트 실행 뒤). load: 이미지, 스타일시트 같은 모든 리소스까지 받은 시점. 보통 DOMContentLoaded가 먼저.

function onClick() {

  setN(n + 1);
  setN(n + 1);

  • 3

n이 0일 때 버튼을 한 번 누르면 n은 몇이 될까?

세 줄 모두 렌더링 당시의 n(0)을 보고 0 + 1을 넣는다. React 18은 한 이벤트 안의 업데이트를 묶어서(batching) 한 번만 다시 렌더링하므로 결과는 1.

상태

함수형 업데이트

const [n, setN] = useState(0);

function onClick() {
  setN((p) => p + 1);
  setN((p) => p + 1);
  setN((p) => p + 1);
}
  • 3
  • 1
  • 0
  • 6

n이 0일 때 버튼을 한 번 누르면 n은 몇이 될까?

setN(p => p + 1)은 바로 앞 업데이트 결과(p)를 받아서 계산한다. 0 → 1 → 2 → 3. 이전 값에 기대는 업데이트는 함수형으로 쓴다.

useEffect

useEffect 실행 시점

  • 처음 화면에 나타난(마운트된) 뒤 한 번
  • 렌더링할 때마다
  • 렌더링 전에 한 번
  • 화면에서 사라질 때만
  • 다음 effect가 실행되기 직전, 그리고 화면에서 사라질 때
  • 처음 마운트될 때 한 번
  • 렌더링이 시작되기 직전마다
  • 직접 부르기 전에는 실행되지 않는다

useEffect(fn, [])의 fn은 언제 실행될까?

effect는 화면에 반영(커밋)된 뒤 실행된다. 의존성 배열이 []면 마운트 뒤 한 번. cleanup은 의존성이 바뀌어 effect가 다시 실행되기 직전과 언마운트될 때 실행된다.

key

key로 index 쓰기

  • 항목 순서가 바뀔 때 입력값 같은 상태가 다른 항목에 붙는다
  • 목록이 화면에 나오지 않는다
  • 항목을 추가할 수 없다
  • React가 에러를 던지고 멈춘다

목록의 key로 배열 index를 쓰면 생길 수 있는 문제는?

index는 순서가 바뀌면 같은 항목이 다른 key를 받는다. React는 key로 항목을 짝지어서 상태를 엉뚱한 항목에 붙인다. 추가·삭제·정렬이 있는 목록은 고유 id를 쓴다.

상태

배열 state 바꾸기

  • setList([...list, item])
  • list.push(item)
  • list.push(item); setList(list)
  • list = [...list, item]

state 배열 list에 item을 추가하는 올바른 방법은?

React는 이전 값과 새 값이 같은 객체인지로 바뀌었는지 판단한다. push로 원본을 바꾸고 같은 배열을 넘기면 바뀐 걸 모른다. 항상 새 배열을 만들어 넘긴다.

순서

state가 바뀐 뒤 화면까지

state를 바꾼 뒤 일어나는 일을 순서대로 놓으세요.

  1. state 변경
  2. 컴포넌트 함수 다시 실행
  3. 가상 DOM 비교
  4. 실제 DOM 반영
  5. useEffect 실행

state가 바뀌면 컴포넌트를 다시 불러 새 가상 DOM을 만들고(렌더), 이전 것과 비교해서 바뀐 부분만 실제 DOM에 반영(커밋)한 뒤, 마지막에 useEffect가 실행된다.

같은 요청을 여러 번 보내면 결과가 달라질 수 있는(멱등하지 않은) 메서드는?

멱등: 여러 번 보내도 결과가 한 번 보낸 것과 같음. GET·PUT·DELETE는 멱등하고, POST는 보낼 때마다 새 리소스가 생길 수 있어 멱등하지 않다. 결제 버튼 중복 클릭을 조심하는 이유.

img 태그에 width·height를 지정하지 않으면 가장 나빠지는 지표는?

이미지 크기를 모르면 이미지가 늦게 도착했을 때 아래 내용이 갑자기 밀린다. 이것이 CLS(레이아웃 이동). width·height나 aspect-ratio로 자리를 미리 잡아 두면 막을 수 있다.
