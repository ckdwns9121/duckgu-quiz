모의고사 A 보충: 이벤트 변환과 유지보수 셸

10일 차 메시징 · 11일 차 보안

EventBridge에서 분류와 전달 형태를 분리한다

EventBridge 규칙의 이벤트 패턴은 어떤 이벤트를 대상으로 보낼지 결정한다. 예를 들어 source=partner.orders, detail.status=SHIPPED, detail.region=KR가 함께 맞는 주문을 물류 대상으로 보낼 수 있다. 생산자는 소비자별 API 주소를 직접 호출하지 않고 버스에 이벤트를 발행한다. 대상이 늘거나 조건이 바뀌면 규칙과 대상을 관리하며, 이 분리는 직접 호출의 주소·분기·재시도 코드를 줄인다.

입력 변환기는 선택된 이벤트를 대상에 전달하기 전에 필요한 필드를 추출해 새로운 입력 템플릿으로 구성한다. 예를 들어 원본 detail.orderId와 detail.status를 추출해 물류 대상에 { "id": "주문번호", "state": "상태" } 형식으로 보낼 수 있다. 어떤 이벤트를 보낼지 고르는 패턴과 선택한 이벤트의 전달 형식을 바꾸는 입력 변환은 서로 다른 설정이다. 입력 변환을 켰다고 실패 전달이 없어지는 것은 아니므로 대상 권한·재시도·DLQ를 함께 검토한다.

같은 SQS 큐를 물류·알림·분석이 경쟁 소비하면 메시지는 나뉘어 전달되므로 세 시스템이 모두 필요한 이벤트를 받는 fan-out과 다르다. 로그를 S3에 모아 폴링 Lambda로 분류하는 방식도 구현할 수 있지만 파일 검색·중복·체크포인트·재시도를 직접 관리해야 한다. 서비스의 존재보다 필요한 전달 의미와 운영 책임을 비교한다.

출처: EventBridge 이벤트 패턴, 입력 변환.

Session Manager의 기본 셸과 SSH 터널 기록은 다르다

Session Manager는 관리형 노드의 SSM Agent, 인스턴스 역할, Systems Manager 서비스로 향하는 연결과 작업자의 IAM 허용을 통해 셸에 접근하게 한다. 서버에 SSH 인바운드 포트를 열거나 작업자에게 서버 SSH 키를 배포하지 않는 구성을 만들 수 있다. 사설 노드는 필요한 서비스 엔드포인트·DNS·보안 규칙 또는 허용된 외부 경로를 통해 서비스에 연결해야 한다.

기본 셸 세션의 출력·명령 기록은 지원되는 S3 또는 CloudWatch Logs 세션 로깅을 구성해 중앙에 남긴다. Session Manager를 통한 SSH 연결이나 포트 포워딩은 암호화된 터널의 내용을 같은 방식으로 기록하는 기능이 아니다. 감사 조건이 셸 명령·출력 기록이라면 기본 셸의 로깅 설정과 저장소·암호화·접근 권한을 확인해야 한다.

EC2 Instance Connect Endpoint는 퍼블릭 IP 없는 인스턴스의 SSH 접근을 도울 수 있지만 대상 SSH 연결을 사용하는 방식이다. Client VPN도 사설 네트워크 경로를 제공할 뿐 대상 서버의 SSH 포트·키 관리와 셸 기록을 자동으로 없애지 않는다. 따라서 인바운드 SSH와 SSH 키가 금지되고 기본 셸을 중앙 기록해야 한다는 조건에서는 Session Manager를 비교한다.

출처: Session Manager, 세션 로깅, SSH 연결.
